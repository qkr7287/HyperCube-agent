## 3. 다음에 와서 — 살아 있는지 빠른 확인 (30초)

SSH 접속 후 이 4줄을 차례로 복붙:

```bash
# 1) 컨테이너가 떠 있나? (Up xxx 보여야 정상)
docker ps --filter name=hypercube-agent
```
```bash
# 2) 최근 1시간 안에 데이터 보냈나? (Sent xx messages 보이면 정상)
docker logs hypercube-agent --since 1h 2>&1 | grep -E 'Sent|ERROR|WARN' | tail -20
```
```bash
# 3) CPU/메모리 사용량
docker stats hypercube-agent --no-stream
```
```bash
# 4) systemd 등록 상태 (enabled / active 여야 정상)
systemctl is-enabled hypercube-agent && systemctl is-active hypercube-agent
```

### 정상 패턴

```
1) STATUS = "Up xx hours/days"
2) "Sent N messages to backend" 같은 줄이 자주 보임. ERROR는 거의 없음
3) CPU < 5%, MEM < 200MB
4) enabled / active
```

### 비정상 — 무엇을 봐야 하나

| 증상 | 빠른 확인 | 다음 단계 |
|---|---|---|
| `docker ps`에 안 보임 | `docker ps -a --filter name=hypercube-agent` (Exit 코드 확인) | airgap-install.md § 8.5 |
| `Up`인데 ERROR 도배 | `docker logs hypercube-agent --tail 100` | airgap-install.md § 8.6 (Backend 연결) |
| systemd disabled | `sudo systemctl enable hypercube-agent` | airgap-install.md § 8.9 |
| Docker daemon 자체 안 떠 있음 | `sudo systemctl status docker` | airgap-install.md § 8.3 |

## 4. 다음에 와서 — 로그 가져오기 (빌드 PC에서 분석할 때)

### 옵션 A: 진단 번들 한 방 (권장)

문제 원인을 모를 때 — 아래 한 줄이면 끝. (자세한 내용은 airgap-install.md § 9)

```bash
sudo bash -c '
TS=$(date +%Y%m%d-%H%M%S)
OUT=/tmp/hc-diag-bundle-$TS
mkdir -p "$OUT"
{
  uname -a; cat /etc/os-release; date; uptime
  docker --version; docker compose version
  docker info 2>&1 | head -60
  docker ps -a; docker images
  command -v systemctl >/dev/null && {
    systemctl status docker --no-pager -n 30
    systemctl status hypercube-agent --no-pager -n 30
  }
  ls -la /opt/hypercube-agent/
  cat /opt/hypercube-agent/docker-compose.yml
  grep -E "^(BACKEND|AGENT_HOSTNAME|GPU)" /opt/hypercube-agent/.env
  ls -la /var/run/docker.sock /var/run/utmp /etc/hostname
  df -h; ip addr; ip route
} > "$OUT/system.txt" 2>&1
docker logs hypercube-agent --tail 500 > "$OUT/agent.log" 2>&1
command -v journalctl >/dev/null && journalctl -u docker -n 300 --no-pager > "$OUT/journal-docker.log" 2>&1
command -v journalctl >/dev/null && journalctl -u hypercube-agent -n 300 --no-pager > "$OUT/journal-agent.log" 2>&1
for f in /tmp/dpkg-pass1.log /tmp/dpkg-pass2.log /tmp/dpkg-configure.log /tmp/hc-dockerd.log; do
  [[ -f "$f" ]] && cp "$f" "$OUT/"
done
source /opt/hypercube-agent/.env 2>/dev/null
[[ -n "${BACKEND_API_URL:-}" ]] && {
  curl -v --max-time 5 "$BACKEND_API_URL/api/agents/" 2>&1
  host=$(echo "$BACKEND_API_URL" | sed -E "s|^https?://||; s|[:/].*||")
  echo; ping -c 3 -W 2 "$host" 2>&1
} > "$OUT/backend-reach.txt" 2>&1
tar czf "${OUT}.tar.gz" -C /tmp "$(basename $OUT)"
rm -rf "$OUT"
ls -lh "${OUT}.tar.gz"
'
```

산출물: `/tmp/hc-diag-bundle-YYYYMMDD-HHMMSS.tar.gz` (보통 < 1MB).

USB 마운트 후 복사:
```bash
sudo cp /tmp/hc-diag-bundle-*.tar.gz /mnt/usb/
sudo umount /mnt/usb
```

### 옵션 B: 그냥 컨테이너 로그만

원인이 명확히 Agent 동작 문제일 때는 이거만으로 충분:

```bash
# 마지막 1000줄
docker logs hypercube-agent --tail 1000 > /tmp/agent.log 2>&1
sudo cp /tmp/agent.log /mnt/usb/agent-$(date +%Y%m%d-%H%M%S).log
```

이렇게 하면 이전 버전(`/data/hypercube/260507/Agent/`)은 그대로 보존되고, 새 버전이 별도 폴더에 들어갑니다 → **롤백 시 옛 인스톨러 그대로 다시 실행**하면 됨.

### 5.4. 인스톨러 실행 (덮어쓰기)

기존 컨테이너를 멈출 필요는 없습니다 — 인스톨러가 알아서 새 이미지 로드 + compose up으로 재기동합니다.

```bash
sudo /data/hypercube/$TODAY/Agent/hypercube-agent-installer-*.sh
```

같은 인터랙티브 입력 다시 받습니다. **기본값(Enter)을 그대로 받으면** 이전 설정이 거의 유지되지만, `.env`는 매번 새로 작성되므로 Backend URL은 다시 입력해야 합니다 → 위 § 1의 표를 보고 같은 값 입력.

> **자동 입력으로 빠르게 가려면** (운영 자동화):
> ```bash
> sudo HC_BACKEND_URL=ws://<...> \
>      HC_BACKEND_API_URL=http://<...> \
>      HC_AGENT_HOSTNAME=<...> \
>      HC_GPU_ENABLED=y \
>      HC_AUTO_START=y \
>      HC_ASSUME_YES=1 \
>      /data/hypercube/$TODAY/Agent/hypercube-agent-installer-*.sh
> ```

### 5.5. 업데이트 후 검증

```bash
docker ps --filter name=hypercube-agent
docker logs hypercube-agent --tail 30
docker images | grep hypercube-agent     # 버전 변경 확인
```

Backend 관리자 페이지에서도 "마지막 활동" 시각이 방금 시각으로 갱신됐는지 확인.

## 7. 완전 제거 (Agent 빼고 싶을 때)

```bash
# 컨테이너 + 이미지 + 설정 + systemd 모두 제거
sudo systemctl stop hypercube-agent 2>/dev/null
sudo systemctl disable hypercube-agent 2>/dev/null
sudo rm -f /etc/systemd/system/hypercube-agent.service
sudo systemctl daemon-reload

cd /opt/hypercube-agent && sudo docker compose down
sudo rm -rf /opt/hypercube-agent
sudo docker rmi hypercube-agent:1.0.0

# 이력 폴더는 본인 판단 (보관 vs 정리)
# sudo rm -rf /data/hypercube/
```

Docker 자체까지 제거하려면:
```bash
sudo apt-get purge -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
sudo rm -rf /var/lib/docker /var/lib/containerd
```

## 8. 운영 중 변경하고 싶은 게 있다면

### 8.1. Backend 주소만 바꾸고 싶음

```bash
sudo nano /opt/hypercube-agent/.env
# BACKEND_URL, BACKEND_API_URL 수정 후 저장 (Ctrl+O, Enter, Ctrl+X)
sudo systemctl restart hypercube-agent
# 또는
cd /opt/hypercube-agent && sudo docker compose up -d --force-recreate
```

### 8.2. GPU 모니터링 켜고 끄기

```bash
sudo nano /opt/hypercube-agent/.env
# GPU_PER_CONTAINER_ENABLED=true 또는 false
sudo systemctl restart hypercube-agent
```

### 8.3. hostname 변경

`AGENT_HOSTNAME` 만 바꾸면 Backend에서 새 Agent로 인식돼버립니다 (재승인 필요). 일반적으로 안 바꾸는 게 좋음.
